# MetalBlok: exact conditional weight streaming for DeepSeek-R1 on Apple unified memory

**Artifact date:** 2026-08-12  
**Target:** Apple M5, 24 GB unified memory, macOS/Metal  
**Model:** DeepSeek-R1 671B `UD-IQ1_S`, 140.231 GB in three GGUF shards  
**Detailed implementation:** [V0 architecture](V0_ARCHITECTURE.md)  
**Measured closeout:** [V0 closeout](V0_CLOSEOUT.md)

## Abstract

MetalBlok is a native inference engine for a quantized 671-billion-parameter
mixture-of-experts transformer whose stored checkpoint is 5.8 times larger
than the target computer's physical memory. It treats the SSD as an explicit
level of the inference hierarchy. The model's exact grouped router selects
eight of 256 routed experts, those IDs become file offsets, and only the
selected compressed slices are read. Quant decode is fused into Metal dot
products, so no full dequantized matrix exists.

The accepted V0 preserves the checkpoint's finite-precision combined-KV-B
graph. It stores expanded FP16 non-rotary K and V plus a shared rotary key,
costing 4,005,504 bytes per sequence position. This choice rejects a smaller
real-arithmetic latent reassociation that did not satisfy the numerical parity
gate for this quantized artifact.

Performance comes from four implemented schedules: 128-token layer-major
prefill with per-layer expert unions; a 256 MiB fixed-projection cache; two
aligned slabs that prefetch layer \(L+1\) during layer \(L\); and priority
expert reads overlapped with shared-expert Metal compute. On the measured M5,
the optimized decode moves 13.588 GB in 1,869 logical reads per token and
typically takes 3.1–4.6 seconds depending on current SSD/VM conditions. GPU
execution is roughly 0.5 seconds, so the end-to-end path is storage-bound.

## 1. Claim discipline

| Class | Meaning |
|---|---|
| Exact algebra | True of the model equation. |
| Descriptor-derived | Integer result from GGUF shapes and byte lengths. |
| Implemented | Present in the native production path. |
| Measured | Observed in a named retained log on the M5 host. |
| Proposed | Not part of V0 and not counted as a result. |

Correct token parity is the release gate. Associativity over real numbers,
coherent-looking text, and a faster isolated kernel are not substitutes for
the accepted finite-precision path.

## 2. Exact conditional sparsity

For sparse layer \(\ell\), normalized activation \(x\), expert functions
\(E_e\), and router-selected set \(A\):

\[
y=E_s(x)+\sum_{e=0}^{255}\alpha_eE_e(x)
=E_s(x)+\sum_{e\in A}\alpha_eE_e(x),
\]

because \(\alpha_e=0\) outside the model's exact top eight. The omission is
not prediction. It becomes legal only after the current router finishes.

The grouped DeepSeek router computes

\[
p_e=\sigma((W_Rx)_e),\qquad c_e=p_e+b_e.
\]

It ranks eight groups by the sum of their top two corrected scores, retains
four groups, chooses the top eight corrected experts in that union, and uses

\[
\alpha_e=2.5\frac{p_e}{\sum_{j\in A}p_j}.
\]

Tie ordering is lower ID first. CPU and Metal oracles agree on IDs and weights.

## 3. Complete forward graph

The 61-layer graph uses residual width 7,168; 128 query heads; Q rank 1,536;
KV rank 512; 128 non-RoPE coordinates; 64 RoPE coordinates; 128 value
coordinates; three dense FFN layers; and 58 top-8 MoE layers.

For each layer:

\[
\bar x=RMSNorm(x),
\quad q=W_{QB}RMSNorm(W_{QA}\bar x),
\]

\[
[c;k^r]=W_{KVA}\bar x,
\quad [k^n;v]=W_{KVB}RMSNorm(c),
\]

\[
s_{h,j}=\frac{m_{YaRN}^2}{\sqrt{192}}
[(q_h^n)^Tk_{h,j}^n+(q_h^r)^Tk_j^r],
\]

\[
a=x+W_O\operatorname{softmax}(s)V,
\]

then dense SwiGLU or shared-plus-routed SwiGLU and a second residual. The
distinct Q6_K output head follows final RMSNorm. Activations, scores, router
math, and logits are FP32; persistent K/V is FP16.

The active RoPE layout uses adjacent coordinate pairs. YaRN blends base
frequencies between correction indices 10 and 23 with frequency scale 1/40;
the scale multiplier is \((1+0.1\ln40)^2\).

## 4. Why compact latent KV is not the V0 result

MLA admits the real-arithmetic identities

\[
q^TW_Kc=(W_K^Tq)^Tc,
\qquad
\sum_jp_jW_Vc_j=W_V\sum_jp_jc_j.
\]

They reduce persistent state dramatically. But the exact artifact stores
quantized combined `attn_kv_b`. Moving its projections across attention
changes dequantization, accumulation, and rounding order. V0 therefore caches
the expanded result generated by the stored graph. The exact byte equation is

\[
61[128(128+128)+64]2=4{,}005{,}504\text{ bytes/position}.
\]

This is an explicit negative result: algebraic information equivalence is not
enough to claim token parity under quantization and floating point.

## 5. Storage-compute co-design

The checkpoint payload is never mapped wholesale. Metadata is bounded; model
ranges enter reusable `MTLStorageModeShared` buffers through `pread` with
`F_NOCACHE` and disabled readahead. Four lanes per shard provide 12 workers.

Unconditional layer weights flow through two 368 MB slabs. At layer \(L\),
the other slab begins layer \(L+1\). Router-selected expert slices use a
separate 24-slot arena and urgent queues. Once IDs are known, all 24 slices are
submitted while the GPU evaluates the shared expert.

Dense layers need one Metal command buffer. Sparse layers need three because
the host must see router IDs before constructing exact file ranges. The full
decode uses

\[
3+58(3)+1=178
\]

command buffers. No hot-path allocation is required.

## 6. Blocked prefill

For a prompt tile \(B\), fixed projections are loaded once. At MoE layer
\(\ell\), the required expert set is

\[
U_{\ell,B}=\bigcup_{t\in B}A_{\ell,t}.
\]

Tokens are grouped by expert, each expert is read once, and specialized IQ1_S
2-D kernels reuse compressed rows across assignments. Results scatter to
`[token, rank]` slots and merge in reference rank order. Exactly 1,000 input
tokens completed at 1.69 token/s.

## 7. Measured result

From the same exact checkpoint at position 1,280, the old and optimized paths
matched these greedy anchors:

| Position | Token | Logit |
|---:|---:|---:|
| 1,280 | 270 | 48.1055 |
| 1,281 | 1,990 | 51.7904 |
| 1,282 | 344 | 45.4884 |

The 256 MiB cache and I/O schedule changed per-step traffic from
13,849,970,112 bytes / 1,939 reads to 13,587,632,064 bytes / 1,869 reads. In
the fastest steady interval, effective NVMe reached 4.4–4.6 GB/s and decode
took 3.09–3.22 seconds. The GPU component remained 0.47–0.52 seconds.

Late in the long expanded-KV run, host-wide VM pressure reduced effective
NVMe to roughly 3.1–3.4 GB/s and raised steps to about 4.2–4.5 seconds. The
system counters also recorded 116 swap-outs across five positions through
position 1,848. This does not imply token corruption, but it is evidence that
short-run peak throughput is not sustained indefinitely on the 24 GB host.

An attempted residual/RMSNorm fusion changed the position-1,282 logit to
45.2879. It was deleted despite locally plausible math. A 2 GiB fixed cache
reduced traffic to 11.710 GB but increased 24 GB host compression, so the safer
256 MiB point is the default.

## 8. Safety and observability

The runtime refuses invalid model geometry, sparse/dataless shards, insufficient
memory headroom, corrupt state, context overflow, partial checkpoints, failed
I/O, and Metal command-buffer faults. Checkpoints write `.partial`, flush,
`fsync`, and atomically rename.

Every token records wall/GPU/I/O time; model/NVMe/urgent bytes and reads;
effective bandwidth; aggregate/max service time; peak outstanding requests;
command buffers; dispatches; allocations; exact KV growth; available-memory
delta; pageout/compression/swap deltas; token ID; and logit. Optional layer
profiling and residual fingerprints localize bottlenecks and divergence.

## 9. Boundary of the result

V0 targets one model, checkpoint, and machine. It does not claim one-million
context, direct NAND placement, ANE offload, concurrent serving, independent
runtime logit equality, or multi-model support. The exact 1,000+1,000 run is a
substantial execution proof, not the end of long-context research.

The immediate future priorities are expert-record relayout, parity-tested
quantized QMM prefill, a compact finite-precision KV oracle, and energy
measurement. Each must improve a defensible metric without crossing the token
gate.
