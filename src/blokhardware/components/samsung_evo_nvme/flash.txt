LLM weights must be written to flash in large, sequential blocks. The storage path should prioritize
high-throughput reads, reduced fragmentation, and predictable access patterns so the runtime can
stream model data efficiently.

The flash layout should follow two constraints from the LLM offload literature: FlexGen-style
linear optimization decides which tensors live on GPU, CPU, or disk, and LLM-in-a-flash-style layout
reduces transferred bytes while increasing contiguous flash reads. Random IO is a failure mode to
design away from, not the default.

For the open-source GDS path, reserve an NVMe device that uGDS can bind directly. That device is not
a normal mounted filesystem while uGDS owns it; driver switching between uGDS and kernel NVMe/GDS
must be explicit and documented before any destructive benchmark.
